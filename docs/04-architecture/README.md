# Software Architecture

This section covers senior-level software architecture concepts, design principles, maintainability, modularity, and technical decision-making.

## Goals

After completing this section, readers should be able to explain:

- How to reason about architecture trade-offs
- How SOLID principles apply in real systems
- How Clean Architecture and Hexagonal Architecture differ
- How to define domain boundaries
- How to design modular systems
- How to design shared libraries
- How to maintain backward compatibility
- How to document technical decisions
- How to discuss architecture in senior-level interviews

## Contribution notes

Before adding content to this section:

- Focus on trade-offs, not only definitions
- Avoid presenting any pattern as universally correct
- Include practical examples
- Explain when not to use a pattern
- Keep architecture advice grounded in maintainability and team impact
