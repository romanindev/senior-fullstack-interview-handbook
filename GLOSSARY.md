# Glossary

This glossary explains common terms used across the handbook.

## API

Application Programming Interface. A contract that defines how software components communicate.

## Backward compatibility

The ability to change a system without breaking existing consumers.

## CI/CD

Continuous Integration and Continuous Delivery or Deployment. A set of practices for building, testing, and releasing software safely and frequently.

## Contract testing

Testing that verifies whether a service provider and consumer agree on an API contract.

## Domain boundary

A logical boundary around a business capability or domain concept.

## DX

Developer Experience. The quality of tools, documentation, APIs, and workflows from a developer's perspective.

## Feature flag

A mechanism for enabling or disabling functionality without deploying new code.

## Hydration

The process of attaching client-side JavaScript behavior to server-rendered HTML.

## Idempotency

The property of an operation where repeated calls produce the same effect as a single call.

## Observability

The ability to understand a system's internal state from external outputs such as logs, metrics, and traces.

## Reconciliation

The process React uses to compare previous and next UI trees and decide what changes should be applied.

## Scalability

The ability of a system to handle increased load by adding resources or improving design.

## Technical debt

A design or implementation compromise that may make future changes harder or riskier.
